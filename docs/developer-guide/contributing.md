# Contributing

## Setting up

```bash
git clone https://github.com/timlinux/qgis-news-gatherer.git
cd qgis-news-gatherer
nix develop
pre-commit install
```

## The loop

1. **Open an issue** describing the change: a user story, success criteria and
   the size of the job.
2. **Branch** off `main`.
3. **Build it**, with tests. A feature without tests is not finished.
4. **Update the docs.** `SPECIFICATION.md` for behaviour, this site for how to
   use it, `CHANGELOG.md` for the release notes.
5. **Bump the version** &mdash; patch for a fix, minor for a feature, major
   for a break.
6. **Open a pull request** referencing the issue with `fixes #123`.

## Commits

[Conventional Commits](https://www.conventionalcommits.org/), because the
version bump and changelog follow from them:

```
feat(youtube): add Shorts section
fix(report): restore chapter timestamps
docs(admin): explain the last Thursday schedule
```

## Code style

- `ruff` for linting and formatting; `mypy` for types.
- Docstrings on every module, class and public function.
- Type annotations everywhere; `disallow_untyped_defs` is on.
- Comments explain *why*, not *what*.
- Every file carries an SPDX header:

    ```python
    # SPDX-FileCopyrightText: 2026 Kartoza <info@kartoza.com>
    #
    # SPDX-License-Identifier: GPL-3.0-or-later
    ```

!!! warning "The repository carries lint debt"

    `ruff check` currently reports pre-existing violations, and
    `ruff format` would rewrite a number of files. Do not fold a
    repository-wide reformat into a feature branch &mdash; it buries the
    change. Clean-ups belong in their own pull request.

## Documentation

```bash
nix run .#docs-serve
```

Serves this site at `http://127.0.0.1:8000` with live reload. `nix run .#docs`
builds it once into `site/`.

The [report archive](../reports/index.md) page is generated by
`scripts/generate_reports_index.py` &mdash; edit the generator, not the
markdown.
